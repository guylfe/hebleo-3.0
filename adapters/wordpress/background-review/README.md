## Overlay lifecycle correction after74eadd7

The original adapter omitted settled-overlay retirement. Lead's actual-event repro demonstrated that a due authoritative version c could not be captured after receipt b. This is corrected in the adapter, without changing the shared core or PHP. The supplied failing repro is preserved and now passes. The prevention is executable coverage of repeated later versions, actual restart and reload, and stale-refresh/acknowledgement interleavings rather than only the first learning return.

Both fresh() and start_study_session now hydrate the durable queue and snapshot settled receipts AND pending sibling claims before beginning the authoritative fetch. A settled overlay may be retired only if that exact receipt was already in the snapshot, the response contains its eligible card, and a fresh finite server clock ticket agrees on a version different from both receipt.resultingVersion and receipt.expectedVersion. The reconciliation predicate compares request ID, immutable hash and both versions inside the shared core's own transaction. A receipt arriving during the request, or a newer receipt for the same card, cannot match that captured identity. Clock/owner/scope/epoch guards fence superseded responses. Cards shown by the response are filtered through the current durable queue AND its original pending/burial observation, even after retirement; this prevents an older response resurrecting siblings. Revealed card and study generation are preserved. Explicit rejection recovery releases only the requested rejection's observation fence after its authoritative refresh and durable resolution.
