# Authored source activity contract: RR-FIRST2-01

The first-two source activity reader now rejects malformed activity content before draft save, publication or backup restore. This corrects RR-FIRST2-01 without changing lesson prose, IDs, media or layout.

`textPages.version` remains 1. Versionless pages retain the original text reader and all 20 legacy drafts remain supported. Source activities require `activityVersion: 1`; every other declared value fails. The source reader supports plain reading/completion pages and activity-owned reading/choice pages. Choice kinds must use choice pages; the other authored kinds must use reading pages. Unsupported versions also fail before reader dispatch.

The contract checks:

| Kind | Required content and model checks |
|---|---|
| memory-first | Digit string, exact ten-second duration, exact/partial authored feedback |
| date-connection | Three string stages preserving every digit, three descriptions, explanation, three titled/text principles |
| memory-comparison | The exact number/date example supported by the current classifier, all six feedback branches |
| letter-gallery | Nonempty bounded items; stable unique item IDs, Hebrew letter, sound, teaching text; alternative text when an image exists |
| letter-input | Single Hebrew answer model, feedback, boolean copy flag; optional letter reference agrees with the answer |
| letter-matching | Four unique item IDs and answer letters, four distinct Hebrew options, complete model references, sounds and feedback |
| self-check | Bounded nonempty sound-model items with stable unique IDs and feedback |
| letter-choice / application-choice | Valid choice answer/index and an authored feedback string for every option; letter-choice options/references agree with the letter model |

Activity IDs, when supplied, must be valid and unique within their page set. Within each gallery, matching or self-check page, no item ID may equal the parent activity ID: parent and child audio actions share that page's lookup namespace. This restriction applies with or without clips and checks every item; item IDs may still be reused on different pages. Audio requires an addressable stable ID. Optional media references must be local strings with safe paths. Missing audio/image fields remain valid: the existing listening UI still explicitly reports unavailable, unfinished recordings. No media or pedagogy is generated by validation.

`schemas/text-pages.v1.schema.json` provides structural type/shape checks. The existing schema semantic pass invokes the same `validateTextPages` contract as the runtime to enforce cross-field cardinality, uniqueness and references; these checks are deliberately not approximated with JSON Schema `uniqueItems` on whole objects. Validation never coerces or rewrites source content.

`test/source-activity-contract.test.js` covers 70 malformed variants through runtime/schema semantics and 350 actual HTTP rejection checks: save, defensive publish of an old malformed persisted draft, and restore corruption in active content, carried history or saved draft. Twelve variants reproduce parent/item collisions across all three item families, without clips, with a child clip, with different parent/child clips, and on the last item. Resolvable synthetic media aliases ensure these fail at the identity guard. Every rejection fingerprints all database tables including sequence/history/media/learner state. Valid route controls, exact current source content, legacy import/restore, and both reader paths are also checked. Positive reader controls observe exact child URLs for gallery/matching/self-check and exact scalar parent URLs for input and both choice kinds; this is dispatch verification, not listening verification. The publish test injects the old malformed draft only to arrange the boundary test; the actual assertion exercises `/api/studio/publish` with its current token.

The four original reviewer reproductions were rerun without modifying their script or historical evidence: all now reject. The five existing installation guards still reject without writes.

This is a bounded contract correction. It does not establish new native/Guy acceptance, install isolated consonant audio, publish external content or change main. Final installation evidence and exact commits are in the current delivery receipt supplied to Leo.
