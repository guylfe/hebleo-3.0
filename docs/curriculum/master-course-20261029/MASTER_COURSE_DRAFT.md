## Shared authoring and build conventions

### Authority and review

This is the master course authoring document. It specifies lesson content and intended behavior; it is not a published course. The first ten lessons are Draft for Guy’s review. Later lessons are Planned from the current A2 route. The approved structure does not constitute approval of the new linguistic wording, answer keys, Nikkud or assets. After Guy approves a lesson, its approved revision becomes the build specification.

### One maintained document

Expand the planned entries in this document, preserving lesson IDs and existing comment anchors. The Google Doc is the editable authoring master; local JSON/Markdown files are dated delivery snapshots. Future work starts by reading this document and reconciling changes before updating snapshots. The curriculum sheet supplies the sequence overview. Vocabulary/media libraries retain their canonical records; this document specifies the intended selections, forms and behavior.

### Navigation and identity

The course index links to every lesson heading. Position is a display value; IDs are stable and must not change when a lesson moves. Screen and exercise IDs describe content rather than current page number. Each planned lesson already has a permanent section that can be expanded in place.

### Statuses

Planned = route entry only. Draft = complete proposed lesson awaiting review. Approved = Guy approved the identified revision. Built = entered in the course at a recorded version. Verified = checked against that approved revision in the course. Keep approval and build/verification dates separately; a built draft is still not approved. All ten current entries: content Draft; approval Pending; build Not started; course verification Not started.

### Learner path and breaks

Default path: Learn → Check → Vocabulary → Apply → Continue. Embedded checks stay beside the explanation they serve; the outer Check/Vocabulary/Apply stages are not duplicated inside Learn. [NEXT PAGE] marks a learner-controlled screen break, not a printing page break. Back is available; ordinary reading never advances automatically. Each heading called Screen contains exact learner copy, followed by author-only behavior/assets.

### Reading and pronunciation

English explains; Hebrew is the learning target. Hebrew samples must retain right-to-left order, with English and numbers isolated where needed. Native recordings are required wherever audio is specified. /sound/ labels are approximate reading guides, not a replacement for native audio. Self-recording or pronunciation grading is not assumed. Placeholder audio/images are author instructions and must not appear to learners as broken controls.

### Nikkud and forms

Vocabulary preserves explicit full, standard unpointed and curated fields. All newly supplied pointing is a draft for review; source pointing is recorded separately. Initially the curated field uses the proposed full model. Vowel-recognition tasks lock the displayed marks. In word recall, optional vowel marks and sentence-ending punctuation are ignored, while letters and word order remain significant. Distinct source/full and standard spellings require explicit accepted alternatives; do not remove vowels to invent standard spelling. No broad typo tolerance.

### Multiple choice

Display every authored option. Keep the written order for an initial build; if shuffling is later enabled, attach feedback to option identity, not its letter. A selected option alone reveals nothing: Select → Check → feedback. Correct: Continue. Incorrect: Retry or Reveal answer, followed by an opportunity to answer again. Mark attempted-with-help separately from independent correctness; do not invent a numeric mastery threshold.

### Typed and ordering

Typed: prompt → attempt → Check → answer-specific feedback; trim surrounding spaces, collapse repeated spaces, ignore case for English-letter reading answers, and allow only the stated alternatives. “I cannot recall yet” reveals a model, then permits a retry. Ordering: show exactly the supplied token pool, use an RTL answer area, Check only after placement, then compare with the specified order. Punctuation is supplied separately unless it is the target.

### Matching and self-check

Matching: show all listed prompts and the full response pool, one-to-one unless stated otherwise. Check after all pairs; retain correct pairs and retry misses. Self-check: spoken or written attempt → Reveal model → learner marks Matches / Needs practice. Open personal responses use the stated criteria, never a single exact-string grader. An inaccessible audio/image task must have an equivalent meaningful alternative; if the tested listening skill cannot be provided, label that skill untested rather than pretend text measures it.

### Vocabulary display and practice

Cards show meaning, pronunciation, current forms and learner notes. Do not show future plurals, roots, patterns or conjugations merely because they exist in the source. Source fields are preserved verbatim as author reference; absent fields mean not supplied, not necessarily inapplicable. Full/standard/curated display forms are explicit proposed fields; curated initially equals full. Unbound entries have no approved root, paradigm or media inferred for them. All recordings below are required placeholders until verified. The Vocabulary stage has study/reveal controls but no hidden extra graded exercises; all checks are authored explicitly below. Practice may combine several words in a coherent exchange. Separate meaning retrieval is appropriate when sentence grammar is not yet available.

### Completion and optional work

Core screens and exercises are attempted; corrections may be revisited before Continue. Optional exercises and handwriting downloads do not block completion. Personal memory or spoken tasks do not claim automated correctness. Record the actual exercise outcome and whether help was used. Any change to these rules during implementation must return here as a reviewed specification change.

### Sources and proposed wording

The route is the live A2 read on 29 October 2026. Original presentation text/notes and mnemonic text were inspected from saved source captures; recordings were not watched or transcribed in this task. Earlier first20 authoring work is acknowledged in the affected lesson notes but its old order is not reused. Unless a field is expressly marked source-verbatim, learner prose, exercises, feedback, example contexts and new display forms are proposed adaptations drafted for this document.

### Build handoff per lesson

Before marking Approved, resolve specific author questions and exact display/answer forms. Before Built, attach the required media or deliberately choose an approved accessible alternative; bind every vocabulary sense to its canonical entry; record the implemented lesson/version. Before Verified, check actual screens, RTL, audio, answer acceptance, retry/reveal, navigation and the approved sequence. Do not silently fill a missing asset or linguistic decision in the course.

## 001 · How memory works — MEMORY-A2

Content: Draft · Approval: Pending · Built version: — · Verified version: — · Revision: 1 (29 October 2026)

OUTCOME: Try recall before reveal, compare with the model, and return after another task.

CONNECT TO: Use a familiar image or meaningful connection to recover something new.

PREREQUISITES: None.

PLAN: https://docs.google.com/spreadsheets/d/1jlSH8qDBt3nwv90J_2IKkL-pzbRx3USW522KqtXR0Nc/edit#gid=102626001&range=A4:M4

SOURCES / ADAPTATION: Original presentation slides 7–10; current A2 row 4. Earlier first20 memory draft used as an adaptation reference.

DESIGN DECISIONS: The current plan uses familiar pictures and delayed recall. The old timed number/date demonstration is not inserted into this route; no learning-speed claim is carried over.

### Learn — exact text and embedded interactions

#### Screen 1: Try before looking · MEMORY-A2.learn.try-first

LEARNER TEXT:

Welcome to Hebleo. Throughout this course, we will connect new Hebrew to something you already know. Before we meet any letters, try a small memory experiment.

You will see three familiar objects. Look at them, then hide them and try to name them. This is practice, not a score of your memory.

[NEXT PAGE — learner selects Continue]

#### Screen 2: Look, hide, remember · MEMORY-A2.learn.picture-round

LEARNER TEXT:

Press Show pictures. Name each object in a language you know. When you are ready, press Hide pictures and tell yourself what was there.

[PLACEHOLDER / AUTHOR INSTRUCTION] IMAGE MEMORY-OBJECTS: three separate, equally clear pictures: a plain drinking cup, a door key, and an apple. No printed labels while visible. Provide equivalent spoken descriptions for nonvisual use.

[PLACEHOLDER / AUTHOR INSTRUCTION] CONTROL: Show pictures → Hide pictures → spoken or typed attempt → Reveal pictures. No timer. Reveal is also available after “I cannot recall yet”.

#### MEMORY-A2.embedded.objects-first — self-check

LEARNER PROMPT: After hiding the pictures, name the three objects.

ANSWER / ACCEPTED MODEL: cup | key | apple

FEEDBACK: Compare object identities, in any order. Synonyms and any language are fine. Missing an object is a reason to look again, not a failure.

[NEXT PAGE — learner selects Continue]

#### Screen 3: Make a connection · MEMORY-A2.learn.connection

LEARNER TEXT:

Now give the objects a familiar setting. Imagine an apple beside your usual cup, with your key between them. If that setting is unfamiliar, choose one of your own.

The useful part is the connection you can bring back to mind. It does not have to be clever or the same as someone else’s. When we learn letters, a familiar image can help you recover a shape and its sound.

[NEXT PAGE — learner selects Continue]

#### Screen 4: Do something else briefly · MEMORY-A2.learn.intervening-task

LEARNER TEXT:

Leave the three objects for a moment. Look at the shapes below and choose the one that matches the outline. Then continue without reopening the pictures.

[PLACEHOLDER / AUTHOR INSTRUCTION] IMAGE MEMORY-SHAPES: unlabelled triangle outline; response shapes circle, triangle, square. Accessible labels identify the three shapes. For nonvisual use, prompt “Which of these shapes has three sides?”

#### MEMORY-A2.embedded.shape-break — multiple choice

LEARNER PROMPT: Which shape matches the triangular outline?

OPTIONS / TOKEN POOL:

A. circle

B. triangle

C. square

ANSWER / ACCEPTED MODEL: triangle

FEEDBACK after “circle”: A circle has a curved edge. Look for three sides.

FEEDBACK after “triangle”: Yes. The outline has three sides.

FEEDBACK after “square”: A square has four sides. Look for three.

[NEXT PAGE — learner selects Continue]

#### Screen 5: Try again after a gap · MEMORY-A2.learn.return

LEARNER TEXT:

Before looking back, name the objects once more. If it helps, revisit the scene you imagined. Then compare with the pictures.

We will use this rhythm in the course: meet something new, connect it to something familiar, try to recall it, and meet it again later.

#### MEMORY-A2.embedded.objects-return — self-check

LEARNER PROMPT: Name the three objects again before revealing them.

ANSWER / ACCEPTED MODEL: cup | key | apple

FEEDBACK: Compare with the same three pictures. Notice which connection helped you; neither improvement nor perfect recall is required.

[NEXT PAGE — learner selects Continue]

### Check — understanding

#### MEMORY-A2.check.useful-anchor — multiple choice

LEARNER PROMPT: What makes an association useful?

OPTIONS / TOKEN POOL:

A. It connects the new item to something familiar to you.

B. It must be complicated.

C. It guarantees that you will never forget.

ANSWER / ACCEPTED MODEL: It connects the new item to something familiar to you.

FEEDBACK after “It connects the new item to something familiar to you.”: Yes. A familiar connection gives you a way back to the new item.

FEEDBACK after “It must be complicated.”: A simple connection can work. Complexity is not the aim.

FEEDBACK after “It guarantees that you will never forget.”: You may still forget. Recall and later practice remain part of learning.

#### Screen 2: Recover the first pair · MNTL-A2.learn.pair-retrieve

#### MNTL-A2.embedded.nun — multiple choice

LEARNER PROMPT: Listen, then choose the letter.

SUPPLIED MATERIAL: AUDIO MNTL-N: isolated /n/.

OPTIONS / TOKEN POOL:

A. מ

B. נ

ANSWER / ACCEPTED MODEL: נ

FEEDBACK after “מ”: מ represents /m/. The sound you heard was /n/.

FEEDBACK after “נ”: Yes: נ represents /n/, as in nose.

[NEXT PAGE — learner selects Continue]

#### Screen 3: Two more shapes · MNTL-A2.learn.tav-lamed

LEARNER TEXT:

ת represents /t/, as at the start of tripping. Its name is Tav.

ל represents /l/, as at the start of ladle. Its name is Lamed.

Use the tripping image for ת and the ladle image for ל. Say each sound, look away, and picture the printed shape.

[PLACEHOLDER / AUTHOR INSTRUCTION] AUDIO MNTL-T: isolated /t/; AUDIO MNTL-L: isolated /l/.

[PLACEHOLDER / AUTHOR INSTRUCTION] IMAGE MNTL-T and MNTL-L: Guy’s original tripping and ladle drawings. Preserve the source drawing rather than substituting a new mnemonic.

[NEXT PAGE — learner selects Continue]

#### Screen 4: Make the shape yourself · MNTL-A2.learn.typing

LEARNER TEXT:

Choose the matching printed letter on the Hebrew keyboard. You may use the on-screen keyboard.

Copying a visible shape helps you locate its key. In the next exercise, the shape will be hidden so that you can try to recall it.

[PLACEHOLDER / AUTHOR INSTRUCTION] KEYBOARD: highlight the matching key only during copying. Hide the highlight for recall questions.

#### MNTL-A2.embedded.copy-lamed — typed

LEARNER PROMPT: Copy this letter: ל

ANSWER / ACCEPTED MODEL: ל

FEEDBACK: Correct: ל. Use the same printed form; handwriting is not required.

Listen to each model and notice where the dot sits. We will use these forms in words now and compare alternative vowel signs in the next lesson.
